# Content Strategy

## Editorial principle

The site should convert expertise into **evidence**.

Priority order:

1. Build and document real work.
2. Turn meaningful work into case studies.
3. Turn lessons into technical writing.
4. Distribute through LinkedIn and GitHub.
5. Route relevant readers back to the site.

## Three content pillars

### 1. Build in public

Main narrative: building AHMED AI OS and selected AI systems.

Examples:

- Building an AI Operating System — Part 1
- Designing memory for AI agents
- Building an evaluation layer for agentic systems

### 2. AI engineering

Topics may include, where supported by actual work:

- LLM applications
- RAG
- AI agents
- agent evaluation
- LLMOps
- deployment
- observability
- inference
- fine-tuning
- system architecture

### 3. AI × business

Topics may include:

- business process automation
- AI-enabled operations
- AI product prototyping
- lead-generation automation
- lessons from building digital products

## Research content

Research content should remain scientifically rigorous.

Never invent:

- experimental values
- statistical results
- references
- publication status
- conclusions

When work is ongoing, label it clearly as ongoing.

## Case-study formula

Each case study should aim to include:

1. Problem
2. Context
3. Requirements
4. Architecture
5. Technology choices
6. Implementation
7. Evaluation
8. Results
9. Challenges
10. Lessons learned
11. Next steps
12. Demo / repository

## Content-to-conversion pattern

```
Insight
  ↓
Evidence
  ↓
Relevant project
  ↓
Case study
  ↓
CTA
```

## Launch content priority

Before publishing a high volume of articles, create strong evidence for:

- AHMED AI OS
- one or more AI engineering projects
- StoryKids
- research profile

A small number of deep, well-supported pieces is preferred over a large number of generic articles.
